# AI稼働容量に応じた可変運用ルール

基準日：2026-09-11
目的：ChatGPT／Claude／Codexの利用可能量・接続状況が変わっても、品質基準と責任境界を崩さず制作を継続する。

## 1. 原則

- 固定するのは「責任」と「品質ゲート」。実行者は容量・接続状況に応じて入れ替えてよい。
- 同じ作業を複数AIへ重複依頼しない。成果物の主担当は常に1つにする。
- AIの残量は推測しない。ユーザー申告、実際の利用可否、接続結果を根拠に切り替える。
- 容量不足を理由に、専門境界を越えて精度を落とす代替はしない。できない工程はキューに積む。
- 公開・投資・課金価値の最終判断は常に山本悠希。

## 2. 通常時の主担当

- ChatGPT：G1企画、G2調査圧縮、SEO、読者設計、画像、CTA、X、販売導線、案件進行、実装仕様、最終UI確認。
- Claude：G3財務・資産分析、反証、リスク、シナリオ、G4ブログ／note本文、分析文章の整合。
- Codex：リポジトリ実装、リファクタ、テスト、機械的な修正、静的監査、ビルド補助。
- 山本：方向性、投資判断、公開判断、価格・課金価値の最終判断。

## 3. 代替可能な範囲

- ChatGPT ⇄ Codex：コード実装、UI修正、SEOメタ実装、内部リンク、CTA部品、監査スクリプト、テストは相互代替可。
- ChatGPT → Codex：仕様が確定していれば、Codexへ実装をまとめて渡してよい。
- Codex unavailable：ChatGPTがRemote Desktop経由で直接実装してよい。
- Claude available：高難度分析・本文へ集中させ、UI・SEO・SNS・コード作業は原則渡さない。

## 4. 代替しない範囲

- 財務・資産分析、反証、シナリオはClaude担当。Claudeが使えないときは待機キューに置き、ChatGPTやCodexで代替分析しない。
- ブログ／noteの分析本文はClaude担当。ChatGPT／Codexは構造・誤字・導線・メタ情報など機械的編集まで。
- 有料商品の販促に評価ランク、目標株価、期待株価、売買判断を持ち込まない。
- 一次資料にない将来計画、未確認数値、架空URLを埋めて先へ進めない。

## 5. 容量モード

### 通常モード
既定の役割分担で進行。Claudeは分析・本文、ChatGPTは企画・販促、Codexは実装。

### Claude節約モード
新規G3/G4を優先案件だけに絞る。ChatGPT＋CodexでSEO、導線、UI、内部リンク、商品棚、監査、自動化を先行し、Claude投入パックを作り貯める。

### ChatGPT節約モード
既に仕様化済みの実装はCodexへ寄せる。ChatGPTは優先順位決定、レビュー、短い販促、引継ぎに限定。Claudeへは分析だけを渡す。

### Codex／Remote Desktop停止モード
ChatGPTは仕様・差分案・検証条件まで作る。接続復旧まで本番変更を断定しない。GitHub読取だけで実装済みと扱わない。

### 全体節約モード
公開期限、セキュリティ、壊れた表示、法務レッドフラッグを最優先。新規企画・大規模リファクタ・装飾改善は停止する。

## 6. 切替判断の順番

1. その作業に必要な専門能力を決める。
2. その能力を持つAIが現在使えるか確認する。
3. 締切・公開影響・セキュリティ影響で優先度を決める。
4. 代替可能なら担当を変更し、代替不可なら待機キューへ入れる。
5. 引継ぎ票に「完了済み／未実施／次に必要な成果物」を残し、再開時の再説明を防ぐ。

## 7. セッション開始時の確認

- 直近の締切と公開予定。
- Claude／ChatGPT／Codex／Remote Desktopの利用可否。残量は推測しない。
- Gitのbranch・未コミット・originとの差分。ユーザー作業を上書きしない。
- 前回の【次AIへの引継ぎ】と案件台帳。
- 本番変更ならprecheck → build → 差分確認 → 公開承認 → deploy → 本番確認 → 更新日時／掲示板 → backupの順を守る。

## 8. 運用上の合言葉

**担当AIを固定しすぎない。責任境界と検証手順は固定する。**

容量が余っているAIへ仕事を寄せるのではなく、「そのAIで安全に代替できる仕事」を寄せる。これにより、Claude復活後もCodexを実装担当として残し、ChatGPTは編集・企画・販促へ戻すなど、案件ごとに柔軟に構成を変えられる。
